# ografstudio.org

The website for [OGraf Studio](https://github.com/zerodensity/ograf-studio), built with
[Docusaurus](https://docusaurus.io/) 3.

| Section | Path | Source |
| --- | --- | --- |
| Home | `/` | `src/pages/index.tsx` |
| Docs | `/docs` | Imported from the Studio repository, plus `docs/index.mdx` |
| How-to guides | `/guides` | `guides/` |
| Examples | `/examples` | `examples/`, with gallery cards in `src/data/examples.ts` |
| What's new | `/releases` | Imported from the Studio repository's release notes |
| Announcements | `/announcements` | `announcements/` |

## Run locally

Node.js 20 or newer:

```sh
npm ci
npm start
```

`npm run build` produces the static site in `build/`, and `npm run serve` serves that build.
`npm run typecheck` checks the TypeScript.

## Documentation and release notes

The pages under `/docs` and every post under `/releases` come from the public
[zerodensity/ograf-studio](https://github.com/zerodensity/ograf-studio) repository, so they match
the latest stable release. Refresh them with:

```sh
npm run import:docs                 # the stable branch
npm run import:docs -- --ref dev    # another branch, tag or commit
```

The script clones the repository into `.cache/`, converts `docs/*.md` and `docs/releases/*.md`,
and rewrites their links for the site. Generated files
carry a "Generated by scripts/import-ograf-docs.mjs" comment and are replaced on every run, so edit
the source documents in the Studio repository instead. A new `docs/*.md` upstream appears in the
Docs sidebar automatically; give it a fixed place in `KNOWN_DOCS` in the script.

The site is public. `--source <checkout>` refuses a checkout whose origin isn't the public
repository, so unpublished work from a private fork can't end up on the site by accident.

The deploy workflow imports on every build and once a day, so what's published on `stable` reaches
the site by itself. To document a build that isn't public yet, import it with:

```sh
npm run import:docs -- --source ../ograf-studio-dev --ref dev --allow-unpublished
```

That run links to the public `stable` branch. Take the import out of `deploy.yml` while it's in use,
or the next deploy puts the public documents back.

The repository's single `docs/USER_GUIDE.md` becomes the many pages under `docs/user-guide/`.
`scripts/user-guide-pages.mjs` holds the sections and says which text goes on which page. If an import
warns about a cut or an unlisted section, the guide has changed upstream: update that file.

## Live examples

Example pages and the homepage play real OGraf packages in the browser with the OGraf web player.
Visitors can take each graphic in and out and edit its data fields live.

- `graphics/<slug>.ograf.zip` are packages exported from Studio with **Export .ograf.zip**. Before
  `npm start` and `npm run build`, `scripts/extract-graphics.mjs` unpacks them into
  `static/graphics/<slug>/`, copies each ZIP there for download, and lists their manifests in
  `src/data/graphics.json`.
- `static/player/ograf-player.js` is the web player. It's served as a static module, not bundled,
  because it imports each graphic's `main.js` at run time.
- `src/components/OGrafExample` mounts a package when it scrolls into view, takes it in, and builds
  the data form from the manifest's schema.
- `src/components/PlayerBackdrop` sets what shows behind every player, and the swatches that change
  it: dark checker (the default), a custom colour, the visitor's webcam or an image they load. The
  player itself is transparent, and the choice is shared by all players on the site. A custom colour
  is remembered between visits. The webcam and image stay in the browser and are never remembered.
  The webcam only starts from a click, stops when no player is left on the page, and needs HTTPS or
  localhost. The reel can also show it on the monitor in its Transition Logic slide, with or without
  making it the background.

To add one, export the graphic from Studio and save it as `graphics/<slug>.ograf.zip`. For an
overlay, tick **Transparent** in the composition settings first, otherwise it plays on solid black.
Then put `<OGrafExample slug="<slug>" />` in an `.mdx` page. Packages run their JavaScript in the
page, so only add graphics you exported yourself.

To update the player from a Studio checkout:

```sh
npm run sync:player -- --source ../ograf-studio
```

## Add content

- **Announcement:** add `announcements/YYYY-MM-DD-slug.md` with `title`, `slug`, `description`,
  `authors` and `tags` front matter, and a `<!-- truncate -->` marker after the opening paragraph
  (`{/* truncate */}` in `.mdx`). Tags must exist in `announcements/tags.yml`, and authors in
  `announcements/authors.yml`.
- **Guide:** add a page to `guides/` with a `sidebar_position`, and link it from
  `guides/index.md`.
- **Example:** add its package to `graphics/` (see above), an `.mdx` page to `examples/` with
  `<OGrafExample slug="…" />`, a 16:9 screenshot to `static/img/examples/` for the gallery card,
  and a card to `src/data/examples.ts`. Put other downloadable files in `static/downloads/`.
  Then make the picture a shared link to the page shows, in Teams, Slack and the like: push the page,
  run `npm run share-cards -- <slug>` (it takes the graphic from the live site; set
  `SITE=http://localhost:3000` to use `npm start` instead), and add
  `image: /img/share/<slug>.jpg?v=1` to the page's front matter. When you remake a card, raise its
  `?v=`: chat apps keep the picture they once fetched from an address.

Pages use plain Markdown (`.md`) unless they need components (`.mdx`). The build fails on broken
links, so check with `npm run build` before pushing.

## Deploy to ografstudio.org

`.github/workflows/deploy.yml` builds and publishes the site to GitHub Pages on every push to
`main`, and daily so new Studio releases appear without a commit. An Actions deployment ignores
`static/CNAME`, so the custom domain is set in the repository's settings.

One-time setup:

1. Push this folder to `zerodensity/ografstudio-site`. It must be public, because the organisation is
   on the free plan.
2. Verify the domain first, so no other repository can claim it: in the organisation's
   **Settings → Pages**, add `ografstudio.org`, then add the TXT record GitHub shows.
3. In the repository's **Settings → Pages**, set **Source** to **GitHub Actions**, then re-run the
   workflow.
4. In the domain's DNS zone (SiteGround), add these records for `ografstudio.org`:

   | Type | Name | Value |
   | --- | --- | --- |
   | A | `@` | `185.199.108.153` |
   | A | `@` | `185.199.109.153` |
   | A | `@` | `185.199.110.153` |
   | A | `@` | `185.199.111.153` |
   | AAAA | `@` | `2606:50c0:8000::153` |
   | AAAA | `@` | `2606:50c0:8001::153` |
   | AAAA | `@` | `2606:50c0:8002::153` |
   | AAAA | `@` | `2606:50c0:8003::153` |
   | CNAME | `www` | `zerodensity.github.io` |

5. In the repository's **Settings → Pages**, enter `ografstudio.org` as the custom domain, wait for
   the DNS check, then turn on **Enforce HTTPS**.

If the repository name or owner changes, update `organizationName` and `projectName` in
`docusaurus.config.ts`.
